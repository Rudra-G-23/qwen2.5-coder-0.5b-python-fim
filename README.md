# qwen2.5-coder-0.5b-python-fim

Fine-tuning **Qwen2.5-Coder-0.5B** for Python fill-in-the-middle (FIM) autocomplete using LoRA on Kaggle GPUs, evaluated with execution-based benchmarks, and deployed locally via Ollama.

## Project Goal

Train a fast, locally-deployable Python autocomplete model — the best FIM accuracy achievable within the 0.5B / millisecond-latency class — and rigorously evaluate whether fine-tuning actually helps using standard benchmarks (not subjective impressions).

## Repository Structure

```
qwen2.5-coder-0.5b-python-fim/
├── src/
│   ├── data_prep.py       # Build FIM prefix/suffix/middle triples from Python files
│   ├── train_lora.py      # LoRA fine-tuning via Unsloth (or plain PEFT fallback)
│   ├── evaluate.py        # Base vs LoRA-FT comparison: exact match, edit similarity, plots
│   └── convert_gguf.py    # Merge adapter → GGUF → Ollama Modelfile
├── configs/
│   └── lora.yaml          # All hyperparameters — change here, never in the scripts
├── notebooks/
│   └── kaggle_train.ipynb # Thin Kaggle controller: clone → install → train → eval
├── local_tests/
│   └── test_data_prep.py  # Unit tests for data pipeline (no GPU needed)
├── data/                  # .gitignored — generated by data_prep.py
├── results/               # .gitignored — metrics CSV + plots written by evaluate.py
└── logs/                  # Project notes, plan, and this guide
    ├── python-fim-0.5b-project-plan.md
    └── HOW_TO_PRODUCE.md  # Step-by-step production guide
```

## Workflow

```
Write code (VS Code / WSL)
        │  git push
        ▼
GitHub repo
        │  Kaggle: git clone
        ▼
Kaggle Notebook (GPU T4)
        ├── data_prep.py  →  FIM triples JSONL
        ├── train_lora.py →  LoRA adapter
        └── evaluate.py   →  metrics.csv + plots
                │  push_to_hub
                ▼
        Hugging Face (adapter only, ~100MB)
                │  merge + convert
                ▼
        GGUF → Ollama → Continue (VS Code)
```

## Quick Start (local, no GPU)

```bash
# 1. Clone and set up
git clone https://github.com/Rudra-G-23/qwen2.5-coder-0.5b-python-fim.git
cd qwen2.5-coder-0.5b-python-fim
python3 -m venv .venv && source .venv/bin/activate
pip install transformers peft datasets pyyaml matplotlib seaborn pandas pytest

# 2. Generate FIM dataset from this repo's own source files
python src/data_prep.py --source-dirs src local_tests --output data/fim_dataset.jsonl

# 3. Run unit tests
pytest local_tests/test_data_prep.py -v

# 4. Verify config loads
python src/train_lora.py
```

For actual training, see [`logs/HOW_TO_PRODUCE.md`](logs/HOW_TO_PRODUCE.md).

## Key Design Decisions

| Decision | Rationale |
|---|---|
| **LoRA only** (not QLoRA) | 0.5B fits in fp16 on T4/P100 — no memory pressure for 4-bit base |
| **Unsloth** for training | Native Qwen2.5-Coder support, fastest on Kaggle free tier |
| **Config-driven** (`lora.yaml`) | All hyperparameters in one place; notebook contains zero magic numbers |
| **Adapter-only HF push** | ~100MB instead of ~1GB; base model is always re-downloaded fresh |
| **Best checkpoint by val loss** | Prevents reporting an overfit run as the headline number |
| **No logic in notebook** | Notebook is a thin controller; all logic is under version control in `src/` |
